# 修复 bug：多图点位 Marker 点击卡死 + 地图固定

## Summary（摘要）
现象：在 Chrome/Edge 中，**单击带多图的“房子图标”点位 Marker**（如“天穆村的漕运、经房子、天穆村的游泳健儿、生活用具”等）会导致**整页无响应（假死）**。  
目标：地图保持**完全固定**（禁止移动/缩放/旋转交互）；点击点位仅更新右侧详情，不应触发卡死或地图跳动。

涉及文件（用户给定 & 代码确认）：
- `src/components/MapDisplay.tsx`（Marker 与图层 click handler；图标创建；MapController 地图锁定逻辑）
- `src/components/FeatureDetail.tsx`（多图画廊渲染）

---

## Current State Analysis（现状分析）
### 1) 触发路径
- 点位 Marker 在 `MapDisplay.tsx` 中通过 `eventHandlers.click` 调用 `onFeatureSelect(...)`，上抛到 `App.tsx` 的 `setSelectedFeature`，从而渲染右侧 `FeatureDetail`。
- `FeatureDetail.tsx` 在 `feature.images.length > 0` 时渲染横向可滚动画廊（多图情况下会一次渲染多张 `<img>`）。

### 2) 高概率根因：MapController 的“事件回拉式锁定”导致事件风暴
在 `MapDisplay.tsx` 的 `MapController()` 里（之前为了“固定地图”加的逻辑）：
- 对 `movestart/moveend/zoomstart/zoomend` 事件注册了回调；
- 回调内通过 `map.setView(...)` 强制“回拉”到锁定中心与缩放；

这种模式容易形成 **事件 → setView → 再触发事件 → 再 setView** 的反馈环，导致主线程被占满，从而在 Chromium 中表现为“整页无响应”。  
（多图点位更容易触发/放大：点击后右侧会加载/解码多张图片、同时 App 重渲染导致地图层更新压力更大。）

### 3) 放大因素：地图层随右侧 state 更新而重渲染 + icon 每次 render 都重建
- `selectedFeature` 在 `App.tsx` 顶层 state，点击点位会让 `App` 整体重渲染，进而 `MapDisplay` 也重渲染。
- `createCustomIcon(type)` 每次调用都会 new `L.divIcon(...)`，点位数量一多会放大卡顿（React-Leaflet 看到 icon 引用变化可能触发底层更新）。

---

## Proposed Changes（改动方案）
> 原则：先“止血”确保不假死；再做必要的性能优化，保证多图点位点击也丝滑稳定。

### A) `src/components/MapDisplay.tsx`：移除“事件回拉式锁定”，改为“单次设定 + 禁用交互”
**改动点**
1. 删除/禁用以下逻辑（避免 setView 循环）：
   - `enforceLock` 函数（检查偏移后 `map.setView(...)` 的回拉）
   - `map.on('movestart'|'moveend'|'zoomstart'|'zoomend', enforceLock)` 及对应 cleanup
2. 保留并明确为“一次性设定”的初始化逻辑：
   - `map.fitBounds(ARCHIVE_BOUNDS, { animate:false })`
   - `finalZoom` 计算与 `map.setMinZoom(finalZoom); map.setMaxZoom(finalZoom);`
   - `map.setView(adjustedCenter, finalZoom, { animate:false })`
3. 地图固定（完全禁止移动/缩放/旋转交互）通过“禁用 handler + 限制 zoom”实现：
   - `dragging/touchZoom/doubleClickZoom/scrollWheelZoom/boxZoom/keyboard/tap` 全部 disable（已有则保留）
   - （如存在）将惯性关闭：`map.options.inertia = false`（防止尾部惯性引起 move）
4. 旋转：
   - 目标是“完全固定”，因此禁用任何旋转手势/控制入口；如果 `leaflet-rotate`/`rotate` props 会引入手势交互，需要在 MapContainer 或 map 实例上关闭对应选项/handler（按当前库版本可用字段落地）。
5. 去掉不稳定/副作用大的“黑魔法”：
   - 移除对私有字段的 `map.off('click', map._onFocus)`（Leaflet/插件版本差异较大，容易引入不可预期问题）
   - 若仍需处理 focus：用具名 handler + cleanup 的方式 add/removeEventListener，避免事件泄漏

**为什么这样改**
- “禁用交互”才是固定地图的正确手段；“通过事件回拉纠偏”容易产生循环与卡死。

---

### B) `src/components/MapDisplay.tsx`：在图层/点位点击中 stopPropagation（降低插件/地图 click 链干扰）
**改动点**
- 将 `Marker/Polygon/Polyline` 的 `eventHandlers.click` 改为接收事件参数 `e`：
  - `e?.originalEvent?.stopPropagation?.()`
  - `e?.originalEvent?.preventDefault?.()`（视需要）
  - 然后再执行 `onFeatureSelect(...)`

**为什么**
- 避免“点位 click 同时触发 map click/插件 click”，减少地图侧不必要的事件链。

---

### C) `src/components/MapDisplay.tsx`：缓存 icon，避免每次 render 重建（性能优化，降低卡顿概率）
**改动点**
- 将 `createCustomIcon(type)` 改为“按 type 复用”的缓存：
  - 模块级 `const ICON_CACHE = new Map<string, L.DivIcon>()`
  - `getIcon(type)`：若存在则返回缓存，否则创建并缓存
  - `Marker icon={getIcon(point.type)}`

**为什么**
- 点击点位会引发右侧 state 更新，地图层若重渲染则会重复创建大量 icon；缓存可显著降低渲染压力。

---

### D) `src/components/MapDisplay.tsx`（可选但推荐）：让 MapDisplay 在 selectedFeature 变化时不重渲染
**改动点**
- 用 `React.memo` 包裹 `MapDisplay` 导出，并自定义 props 比较：
  - 仅当 `activePeriod.id` 变化时才重渲染（`onFeatureSelect` 为稳定引用时可忽略）

**为什么**
- 你的交互目标是“点击点位只更新右侧”，这一步能确保地图层稳定不抖动。

---

### E) `src/components/FeatureDetail.tsx`：多图画廊图片解码/加载降压（缓解多图点位点击瞬间的主线程压力）
**改动点**
- 给画廊内 `<img>` 添加：
  - `loading="lazy"`
  - `decoding="async"`
- 保留 `aspect-[16/10]` 等固定尺寸以避免布局抖动（当前已有）

**为什么**
- 多图点位点击会同时解码多张大图；异步解码 + 延迟加载可降低“像卡死”的概率。

---

## Assumptions & Decisions（假设与决策）
1. “地图完全固定”的定义：**禁止移动、禁止缩放、禁止旋转**；点击点位只切换右侧详情。
2. 本次卡死以 `MapController` 的事件回拉式锁定为主因，优先移除该模式；若移除后仍有卡死，再追加排查（例如图片体积过大导致长任务）。
3. 优先保证稳定性（不假死）与交互符合预期，其次再做性能优化（缓存 icon、memo MapDisplay、图片异步解码）。

---

## Verification（验证步骤）
1. **复现回归（Chrome/Edge）**
   - 连续点击以下多图点位 Marker（示例）：天穆村的漕运、经房子、天穆村的游泳健儿、生活用具
   - 预期：不出现整页无响应；右侧详情正常切换；多图画廊可横向滚动/点击放大不崩。
2. **地图固定验证**
   - 尝试拖拽、滚轮缩放、双击缩放、触控板缩放/平移、旋转入口（如有）
   - 预期：地图中心与缩放保持不变，无法被用户手势改变。
3. **事件风暴验证（开发者工具/日志）**
   - 点击点位不应触发高频 `move/zoom` 事件链（不应出现持续 setView 调用）。
4. **性能粗检**
   - 多图点位连续点击 20 次：页面仍保持流畅、无明显越来越卡的趋势（排除事件监听泄漏/重复创建 icon 等问题）。
